## Question 2
--backend-store-uri specifies where MLflow stores its metadata. In this case, sqlite:///mlflow.db means the metadata is stored in a local SQLite database called mlflow.db.

--default-artifact-root specifies where MLflow stores the artifacts produced by runs. Here, ./mlruns means they are stored in the mlruns folder inside the repository.

Metadata describes an MLflow run, such as experiment information, run IDs, parameters, metrics, tags, and run status. Artifacts are the actual files generated by the run, such as trained models, plots, images, checkpoints, and other output files.

## Question 3
`mlflow.db` and `mlruns/` should not be tracked by Git because they are local experiment outputs that change frequently and are not part of the source code. Tracking them would create unnecessary commits and can make the repository large and messy.

They also should not be tracked by DVC because DVC is mainly used to version datasets and other large project data that are intentionally part of the reproducible workflow. MLflow already manages its own experiment metadata and artifacts, so storing them in DVC would duplicate responsibilities and add unnecessary complexity.


## Question 4
If set_experiment() is called with a name that does not exist, MLflow automatically creates a new experiment with that name and sets it as the active experiment. The new experiment then appears in the MLflow UI and future runs are logged under it unless another experiment is selected.

## Question 5
mlflow.log_param is used to log configuration values or hyperparameters that describe how a run was performed, such as the learning rate, batch size, number of epochs, or dataset used. These values normally stay constant throughout the run.

mlflow.log_metric is used to log numerical results that can change during training, such as training loss, validation loss, and validation accuracy.

log_metric takes a step argument because the same metric is usually recorded repeatedly over time, for example once after every epoch. The step allows MLflow to associate each value with a specific epoch and display the metric as a curve in the UI. Parameters do not need a step because they are normally logged once and remain fixed for the whole run.

## Question 7
The learning rate 0.0001 gave the best validation accuracy, reaching 0.784 (78.4%). A higher learning rate is not always better. If the learning rate is too high, the optimizer can make updates that are too large and overshoot good solutions, leading to poor convergence. In this experiment, 0.01 performed much worse than 0.0001, showing that the learning rate needs to be tuned rather than simply increased.
